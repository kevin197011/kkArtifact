# Design: 首页项目树根节点

## Context

- 首页使用 Ant Design `Tree`，数据源为 `treeData`，当前顶层为多个项目节点（Project → App → Version）。
- 需求：增加一个根节点，使整棵树可被一次性折叠/展开，便于项目较多时的浏览。

## Goals / Non-Goals

- **Goals**: 增加虚拟根节点；根节点可展开/折叠并控制整棵树的显示；不改变现有搜索、筛选与节点交互。
- **Non-Goals**: 不改变 API 与数据结构；不改变项目/应用/版本层级语义；不做多根或分组等复杂结构。

## Decisions

- **根节点为前端虚拟节点**：仅在 UI 层将现有顶层项目列表包装为根节点的 `children`，不新增后端实体或 API。
- **根节点 key**：使用固定 key（如 `inventory-root`），便于在 `expandedKeys` 中统一控制。
- **默认展开**：根节点默认展开，与当前「进入页面即看到所有项目」行为一致；若产品希望默认收起，可在实现时将根节点 key 从初始 `expandedKeys` 中移除。
- **搜索时展开**：执行搜索并展开匹配路径时，将根节点 key 加入 `expandedKeys`，确保根节点展开以显示下方匹配项。
- **样式**：根节点使用与项目节点可区分的图标/文案（如「全部项目」+ 文件夹或列表类图标），样式与 `InventoryPage.module.css` 一致。

## Risks / Trade-offs

- 多一层节点可能略微增加一次点击才能到达项目，但换来「一键折叠」的收益，且根节点默认展开，对现有习惯影响小。

## Migration Plan

- 纯前端变更，无需数据迁移或后端发布。上线后若需回滚，移除根节点包装逻辑即可恢复原树结构。
